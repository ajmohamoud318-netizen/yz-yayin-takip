Three sibling custom hooks in `client/src/hooks/` each own one resource:
- `useProjects.js` exposes two hooks: `useProjects()` is a thin passthrough to the shared `useProjectsStore` (a Zustand-like store imported from `./useProjectsStore.jsx`) so all screens read/write the same project list; `useProject(id)` fetches a single project via `api.getProject`, then overlays whitelisted scalar fields (`stage`, `progress`, `assigned_to`, etc.) from the shared store onto the locally-fetched detail so the detail view never drifts from the list. Mutations go through `setProject`, which updates both local state and the store via `updateOne`.
- `useMeetings.js` manages the team-wide meeting log (not per-user), fetching once on mount after `useAuth` resolves, and exposing CRUD plus image upload/delete. All mutations are optimistic: they update local state immediately, set a `busy` flag, call the API, and roll back to the previous array on error.
- `useMeetingDetail(meetingId)` is a separate hook for the meeting detail dialog, lazily loading gallery images and notes only when a meeting is opened, with its own optimistic add/update/remove operations.

Dependency direction is one-way: hooks depend on `@/api`, `@/hooks/useAuth`, and `@/lib/image`; there is no cross-import between these three files. The shared project store is the only external state boundary beyond React's built-in `useState`/`useEffect`/`useCallback`/`useMemo`.
