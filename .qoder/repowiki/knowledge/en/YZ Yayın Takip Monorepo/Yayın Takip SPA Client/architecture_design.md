The client follows a layered architecture with a single composition root (`src/application/create-api.js`) that instantiates every `infrastructure/http/repositories/*` (auth, project, order, handover, notification, push, work-log, meeting, demo, product-info, subtask, target-project-idea) and exposes them through a flat `api` object re-exported from `src/api.js`. Presentation layers (`pages/`, `components/`, `hooks/`) import only this facade — they never touch infrastructure directly. Domain logic is split between pure business rules in `domain/services` (pipeline, progress, status styles) and cross-aggregate workflows in `application/use-cases` (order request lifecycle, handover creation/confirmation), which compose multiple repositories to enforce server-side state transitions without leaking HTTP details to the UI. The Axios client in `infrastructure/http/client.js` centralises auth (X-User-Id header via interceptor + localStorage mirror), error translation (offline vs backend errors), and 401-driven logout, so all children share identical session/error semantics.
