Two sibling React page components share a single data layer in `productCatalog.js`:
- `Urunler.jsx` renders the orderable product list, grouped into ready-for-order / already-sold / delisted sections, with role-gated actions (order, delist/relist, manage subtasks). It fetches projects via `api.listProjects`, listens for cross-tab `storage` events to react to edits made in Ürün Bilgileri, and delegates promotion of orphan kayıt seeds to `PromoteRecordDialog`.
- `UrunBilgileri.jsx` renders expandable product cards showing component spec sheets (`SpecSheet` / `EditableSpecSheet`), supports inline editing, deletion, and batch promotion of kayıt rows. It loads server specs via `api.listProductInfo`, merges them over a localStorage mirror, and uses `primeProductInfoCache` to keep both pages consistent.
- `productCatalog.js` is the shared persistence module: an in-memory `serverCache` Map is primed on boot (`hydrateProductInfo`) from the server, falls back to a `localStorage` key (`yz_product_info_overrides_v1`) when offline, and finally to the bundled `PRODUCT_INFO` seed. Reads are synchronous; writes go through `saveComponentsForProject` which updates cache + localStorage immediately and persists to the server asynchronously, with a backfill pass that pushes stale local overrides up to the server once it's available. Helper functions expose a stable shape `{ component, date, fields: [{k,v}] }` consumed by Demo/Ozalit forms.
