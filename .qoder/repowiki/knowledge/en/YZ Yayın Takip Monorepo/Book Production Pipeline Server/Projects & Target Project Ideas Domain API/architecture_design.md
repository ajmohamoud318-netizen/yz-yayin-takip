Two Fastify route modules expose REST endpoints under `/api/projects` and `/api/target-project-ideas`, each delegating to thin service layers. `routes/projects.js` is the central orchestration layer: it attaches users via `attachUser`, enforces `team_leader`/designer roles via `requireRole`, reads projects through `services/project-repository.js`, applies state-machine transitions from `services/project-transitions.js` (`applyAdvance`, `applyApproval`, `applyDemo*`, `applyOzalit*`, etc.), persists changes inside `withTx` transactions, logs history via `logHistory`, and fans out notifications through `services/notifications.js`. A special `POST /projects/import` batch-imports legacy/backlist products in a single transaction with duplicate detection and dry-run rollback. The `approve` route additionally triggers `captureProductInfoFromSpec` from `services/product-info-capture.js` to copy the approved demo/ozalit/baski_onay spec sheet into `product_info` when entering `baskida`. `routes/target-project-ideaRoutes` handles CRUD plus cover-image and gallery-image uploads, enforcing ownership via `assertCanModify` and validating images with content sniffing before persisting via `idea-images.js` / `idea-gallery-images.js`. `services/project-repository.js` is a pure SQL wrapper over the Postgres pool exposing `listProjects`, `getProjectForUpdate`, `patchProject`, `insertProject`, `deleteProject`, `restoreProject`, `setProjectCatalogHidden`, `listProjectSubtasks`, `listProjectHistory`, `loadProjectAssignees`, `insertDemoSnapshot`, and `reconcileOzalitApprovals`; it centralizes column whitelisting (`PROJECT_WRITABLE_COLUMNS`) and row-to-object mapping via `rowToProject`. Dependency direction is strictly routes → services → db/pool; domain helpers (`domain/stages.js`, `domain/pipeline.js`, `domain/errors.js`, `domain/progress.js`) are read-only inputs used by both routes and services.
