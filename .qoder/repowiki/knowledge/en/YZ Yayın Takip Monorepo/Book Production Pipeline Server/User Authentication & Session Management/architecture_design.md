The module is organized as a thin Fastify route layer (`routes/auth.js`, `routes/users.js`) delegating business logic to domain services (`services/sessions.js`, `services/password-resets.js`, `services/invitations.js`), all guarded by shared middleware in `middleware/auth.js`. Routes declare request validation via JSON schemas from `../schemas/index.js` and apply per-endpoint rate limiting through `../middleware/rate-limit.js` (e.g., dual IP+email buckets on `/auth/login`, per-IP+per-token buckets on invite/reset flows). Authentication is resolved in two stages: cookie sessions via `sessions.js` (httpOnly, signed opaque tokens stored in the `sessions` table) fall back to a dev-only `X-User-Id` header when `config.trustHeaderAuth` is enabled; `attachUser` attaches the resolved user row to `request.user`, and `requireRole` enforces `team_leader` or other roles. Passwords are hashed with bcryptjs at cost factor 12. Invitation and password-reset flows follow an identical create→verify→consume pattern using nanoid-generated tokens with TTLs (7 days for invites, 60 minutes for resets) stored in dedicated tables, and both email outages are treated as best-effort so they never block the primary flow. User deletion cascades via FK rules and also removes avatar files from disk.
