Two-layer design: `routes/notifications.js` and `routes/push.js` expose Fastify endpoints that authenticate via `attachUser`, validate input against shared schemas, and delegate to services. The core `services/notifications.js` is the event hub — a single `emit()` inserts one row per recipient into the `notifications` table (multi-row parameterised INSERT) and schedules push delivery via `dispatchPush`, which uses Postgres `afterCommit` hooks so pushes fire only after the caller's transaction commits and never inside it. Delivery follows an outbox pattern: rows are inserted with `pushed_at IS NULL` (owed), `deliverBatch` calls `sendToRecipients` in `push.js`, then marks rows settled or increments `push_attempts`; `sweepPendingPushes` re-delivers still-owed rows on a timer. A separate `notification-maintenance.js` runs two `setInterval` loops (push sweep every 30s, cleanup every 6h) protected by Postgres advisory locks (`pg_try_advisory_lock`) for blue/green multi-instance safety. `services/push.js` wraps `web-push`, lazily configures VAPID keys, caps concurrent sends to 12 via a custom concurrency limiter, classifies results as sent/transient/dead, and marks dead subscriptions before pruning them after a grace period. `services/mail.js` wraps `nodemailer` with a JSON dev transport fallback and renders invite/reset emails. A dedicated test file (`notification-delivery.test.js`) asserts SQL shape of feed queries and the three-way delivery classification logic using a fake pg client.
