The module is organized into two subdirectories. `migrations/` contains a linear sequence of numbered SQL files (001 through 054) applied in order to evolve the database schema; each file documents its purpose in a leading comment block and uses idempotent DDL (e.g., `DROP CONSTRAINT IF EXISTS`) so re-runs are safe on seeded databases. The schema models a multi-role production pipeline (team_leader, designer, printer, satis) with tables for users, projects, subtasks, demos, order_requests, handovers, stage_history, password_resets, sessions, notifications, work_log, meetings, target_project_ideas, and approval-related columns across multiple stages (ozalit, ekran_onay, matbaa_onay, baski_onay). `seed/` provides deterministic fixture data: `users.js` exports `SEED_USERS` with bcrypt-hashed demo passwords, and `slug-uuid.js` converts human-readable slugs like `u-ayse` into stable UUID-shaped identifiers compatible with real `uuid` columns. Migration comments explicitly document state-machine transitions and how schema changes map to UI workflow steps, serving as the canonical record of the application's business rules.
